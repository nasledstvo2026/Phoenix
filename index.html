📐 Описание архитектуры

Зона 1 — Поток запроса. Пользователь отправляет вопрос через мессенджер. Gateway OpenClaw принимает сообщение, Main (в режиме «курьера») распознаёт триггер «Федор» и маршрутизирует запрос к fz425-agent. Агент формирует черновик ответа и через sessions_send вызывает fz425-verifier для проверки всех фактов. После верификации ответ возвращается пользователю с вердиктом.

Зона 2 — База знаний. Три нормативных документа (НК РФ ч.1, НК РФ ч.2, полный текст 425-ФЗ) плюс SKILL.md v2 с приоритетами, проверенными фактами и запретом домыслов. Глоссарий terms.md фиксирует терминологию (ПОС, ПНО, ЕНС, Реестр решений). SKILL.md регулирует протокол: агент не выдумывает, опирается только на подтверждённые факты.

Зона 3 — Embedding-поиск. law-search API на отдельном systemd-сервисе принимает REST-запросы. Векторный индекс FAISS (2981 чанк, время поиска ~45 мс) построен на эмбеддингах multilingual-e5-small (384 измерения, ONNX-рантайм). На входе работает препроцессинг: раскрытие аббревиатур по словарю tz-abbrev-dict.md для повышения точности поиска.

Зона 4 — Инфраструктура. Холодный рестарт гейтвея через safe-restart.sh (12 секунд, systemd-run таймер гарантирует перезапуск). Гейтвей и law-search — независимые systemd-юниты; law-search переживает рестарт гейтвея. Тяжёлые задачи агентов изолируются через sessions_spawn isolated для предотвращения переполнения контекста.
