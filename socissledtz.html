Создать на OpenClaw-инстансе «Феникс» (213.171.25.85) агента «Социальный исследователь» (social-research-agent) для сбора структурированных перечней мер социальной поддержки по всем регионам РФ.

Предметная область: категории социальной поддержки (стартовый набор: инвалидность, ВБД, участники СВО) с возможностью расширения списка Ириной. Все 89 регионов РФ.

Периодичность: раз в квартал, запуск вручную Ириной. Без cron.

Описание предметной области

Мера социальной поддержки — установленная законом или иным нормативным актом форма помощи государства гражданам определённых категорий. Мера может быть выражена в деньгах, льготах, услугах или натуральной помощи.

Уровни законодательства

Меры поддержки устанавливаются на двух уровнях — федеральном и региональном. Для целей агента анализируются оба уровня, с фокусом на региональные меры (федеральные уже покрыты social-consult-agent).

Категории — динамический список

Стартовый набор из трёх категорий, с возможностью добавления новых Ириной через социального консультанта (см. Этап 5):

  • 1. Люди с инвалидностью. Базовый документ: Федеральный закон № 181-ФЗ «О социальной защите инвалидов». Меры различаются по группам (I, II, III), есть специфические меры для детей-инвалидов.
  • 2. Ветераны боевых действий (ВБД). Базовый документ: Федеральный закон № 5-ФЗ «О ветеранах». Три категории ВБД (по подпунктам ст. 3).
  • 3. Участники СВО и члены их семей. Базовый пакет: указы Президента РФ, федеральные законы о статусе военнослужащих. Категории получателей: мобилизованные, контрактники, добровольцы. Отдельно выделяются меры для детей участников СВО.

Источники информации (по региону)

  • Официальный сайт региона (правительство, губернатор)
  • Сайт регионального министерства/департамента труда и социальной защиты
  • Региональные законы и постановления
  • garant.ru, consultant.ru — тексты НПА
  • sfr.gov.ru — информация СФР по региону

Отличие от социального консультанта

Консультант отвечает на конкретные вопросы (SLA 120 с). Исследователь собирает полные перечни мер — это многочасовая задача. Целевое время на регион ~10 минут. Если сбор активно идёт — продлевать. Жёсткий cutoff: 30 минут (защита от реального зависания).

Связь с существующей архитектурой Феникса

  • ✅ Уже есть: main, fz425-agent, fz425-verifier, social-consult-agent, social-verify-agent
  • 🆕 Добавляем: social-research-agent, irina-router
  • ⚠️ Конфликты не ожидаются — агенты изолированы по workspace и trigger
  • Шаблоны запросов (промпты) создаются динамически при добавлении категорий
  • Папки для результатов создаются автоматически под каждую категорию

Накопительный результат

Каждая следующая версия Excel-файла надстраивается над предыдущей. Изменения маркируются: 🆕 новое / ❌ отменено / ✏️ изменено / ▬ без изменений (см. Этап 4, Подзадача 7).

Автономность

Феникс не зависит от Лунтика в runtime. Все скиллы и БЗ создаются и хранятся локально на Фениксе.

Модель

deepseek/deepseek-v4-flash (основная), deepseek/deepseek-v4-pro (fallback).

Этап 4. Логика работы исследователя

Подзадача 0. Архитектурные ограничения

  • 13.1 sessions_spawn ЗАПРЕЩЁН. Исследователь — одиночный агент. Вся работа (web_search, web_fetch, exec python, Excel) делается в собственном процессе.
  • 13.2 Последовательная обработка — строго 1 регион одновременно. Параллельные spawn одного агента конфликтуют на session-файле (EmbeddedAttemptSessionTakeoverError).
  • 13.3 Relay-паттерн: исследователь запущен через sessions_spawn(context="isolated"). Инструменты exec/read/web_search могут быть недоступны в изолированном контексте. В этом случае исследователь отправляет команды irina-router'у через sessions_send, роутер выполняет их и возвращает результат.

3. Ограничения и правила

  1. НЕ трогать fz425-agent и fz425-verifier — работают штатно
  2. НЕ трогать social-consult-agent и social-verify-agent — работают штатно
  3. Запуск только по триггер-фразе от Ирины (sender_id=739016616). Без cron
  4. Последовательная обработка — строго 1 регион одновременно (архитектурное ограничение: параллельные spawn конфликтуют на session-файле)
  5. НЕ додумывать данные — если поле не найдено, «Не указано в найденных источниках»
  6. НЕ экстраполировать данные с одного региона на другой
  7. Шаблоны читать из файлов перед каждой категорией (не кэшировать между запусками)
  8. Категории читать из categories.json при каждом запуске (не хардкодить)
  9. Модель: v4-flash основная, v4-pro fallback
  10. Целевое время на регион ~10 минут. Если сбор активно идёт — продлевать (с записью причины в лог). Жёсткий cutoff: 30 минут (защита от зависания)
  11. Результаты сохранять локально на Фениксе в knowledge/research/
  12. Конфигурацию Феникса править через SSH, не через TUI
  13. Перезапуск Феникса — только через safe-restart.sh
  14. Накопительный Excel: не удалять старые данные, только дополнять и маркировать изменения
  15. sessions_spawn ЗАПРЕЩЁН в социальном исследователе — он одиночный агент
  16. Субагенты исследователя запускаются через sessions_spawn(context="isolated", cleanup="delete") — relay-паттерн для обхода ограничений изолированного контекста
