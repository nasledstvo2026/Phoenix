## Архитектура маршрутизации

### Принцип (утверждён 30.07.2026)
1. **Main — единая точка входа.** Все пользователи → Gateway → main. Никаких прямых bindings на других агентов.
2. **Триггер = имя агента.** Чтобы обратиться к агенту, пользователь пишет его имя-триггер в сообщении.
3. **Main-курьер.** Распознав триггер, main НЕ думает, НЕ анализирует, НЕ проверяет — только:
   - Извлекает имя агента из сообщения
   - Отправляет запрос агенту через `sessions_spawn(agentId="...", context="isolated", cleanup="delete")`
   - Получает ответ
   - Возвращает пользователю как есть

⚠️ **Stateless.** Каждый вызов агента — чистая изолированная сессия, удаляемая после ответа. Накопление контекста исключено.
4. **Без триггера** — main отвечает сам как обычно.

### Список триггеров (см. TOOLS.md)

```
Пользователь: "привет"          → main отвечает сам
Пользователь: "Федор, вопрос?"  → main → fz425-agent → ответ пользователю
```

## ⚡ Рабочие правила производительности (18.08.2026)
- **Простые правки — без овер-разведки.** Для «добавь плашку/страницу» достаточно ОДНОГО `read` целевого файла → сразу `edit`/`write`. НЕ копаться в соседних каталогах, НЕ грепать лишние CSS, НЕ читать чужие html.
- **Проверка деплоя — одна попытка curl.** Если `200` — финиш. Никаких циклов retry.
- **Сеть флакит — сказать сразу.** Пуш ушёл, но проверка не прошла из-за сети → сообщить «пуш ушёл, проверка не удалась (сеть)», а не молча долбить повтор.
